│   ├── ui.js             ← "tela": status, aviso (setTimeout), renderizarLista, renderizarCard

Ordem dos scripts importaNo index.html, os <script> entram na ordem storage.js → api.js → ui.js → app.js: cada arquivo usa funções do anterior. O app.js é o único que "executa" algo no carregamento (chama iniciar()).

3. Responsabilidade de cada arquivo (e o que NÃO fazer)

ArquivoFazNão faz
storage.jsLer e gravar no localStorage; converter JSON; devolver valores padrãoNão mexe no DOM, não chama fetch
api.jsMontar URLs, chamar fetch, checar response.ok, devolver dados limposNão mexe no DOM, não usa localStorage
ui.jsDesenhar na tela a partir de dados recebidos; status e avisoNão busca dados, não grava no storage
app.jsLigar eventos e coordenar os três acima; timers; geolocalizaçãoNão monta HTML na mão (isso é do ui.js)

4. Contratos de dados

ChaveTipo guardadoExemplo de valor (texto)Padrão na 1ª visita

LembreteO localStorage só guarda texto. Objetos e arrays passam por JSON.stringify ao salvar e JSON.parse ao ler. Nunca guarde token, senha ou CPF.

5. A API Open-Meteo

5.1 Forecast (clima atual)

GET https://api.open-meteo.com/v1/forecast
    ?latitude=-25.4284
    &longitude=-49.2733
    &current=temperature_2m,weather_code,wind_speed_10m
    &timezone=auto

Resposta (resumida): os dados "agora" ficam em current.

{
  "current_units": { "temperature_2m": "°C", "wind_speed_10m": "km/h" },
  "current": {
    "time": "2026-10-09T09:30",
    "temperature_2m": 22.4,
    "weather_code": 3,
    "wind_speed_10m": 9.1
  }
}

5.2 Geocoding (nome → coordenadas)

GET https://geocoding-api.open-meteo.com/v1/search
    ?name=S%C3%A3o%20Paulo          ← encodeURIComponent("São Paulo")
    &count=1&language=pt&format=json
{ "results": [ { "name": "São Paulo", "latitude": -23.5475, "longitude": -46.6361, "country": "Brasil" } ] }

// Cidade inexistente → o campo "results" SOME (não vem array vazio):
{ "generationtime_ms": 0.4 }
Confira na fonteOs exemplos acima mostram o formato; os valores reais mudam. Teste no navegador (cole a URL na barra de endereços) e leia a documentação em open-meteo.com. A fonte da verdade é a API e a documentação — não o palpite da IA.

6. Fluxos principais

6.1 Ver o clima de uma cidade

clique em "Ver clima" ──► selecionarCidade(cidade)
      └─► carregarClima(cidade, forcar=false)
            ├─ cache fresco (< 10 min)?  ──► atualizarTela()              (sem rede)
            └─ não: mostrarStatus('Carregando…','carregando')
                    try { buscarClima() → salvarNoCache() → mostrarStatus('…atualizado','sucesso') → atualizarTela() }
                    catch { há cache antigo? → mostra com aviso "Sem conexão…"
                            senão → mostrarStatus('Não foi possível carregar…','erro') }

6.2 Buscar por nome (⭐)

submit do formulário ──► preventDefault() ──► nome vazio? → erro + foco no campo
      └─► buscarCoordenadas(nome)            (Geocoding)
            ├─ null → "Cidade não encontrada" (erro)
            └─ { nome, latitude, longitude } ──► adicionarCidade() ──► carregarClima()

6.3 Atualização automática (⭐)

marcar "Atualizar a cada 10 minutos" ──► iniciarAtualizacao()
      ├─ pararAtualizacao()                      ← nunca 2 timers vivos
      └─ timerAtualizacao = setInterval(atualizarTudo, 10 * MINUTO)
aba oculta (visibilitychange) ──► pararAtualizacao()      aba visível ──► atualizarTudo() + iniciarAtualizacao()

7. Tratamento do "caminho triste"

O que pode dar erradoComo aconteceComo tratar
1ª visita: chave inexistentegetItem → null; JSON.parse(null) → null; forEach quebraJSON.parse(...) || []
JSON corrompido no storageJSON.parse lança SyntaxErrortry/catch devolvendo o valor padrão
Cota cheia ou storage bloqueadosetItem lança errotry/catch e retorno true/false
Rede caídaO fetch rejeitatry/catch + mensagem acessível
Servidor responde 404/500O fetch não rejeita; response.ok é falseif (!resposta.ok) throw new Error(...)
Servidor lento"Carregando…" para sempreAbortController + setTimeout de 8 s; AbortError vira "demorou demais"
Cidade inexistenteGeocoding sem o campo resultsif (!dados.results || dados.results.length === 0) return null
Código de tempo desconhecidomapa[code] é undefinedmapa[code] || { texto: 'Condição desconhecida', icone: '❓' }
Geolocalização negada/indisponívelCallback de erro; ou navigator.geolocation inexistenteAvisar e focar o campo de busca (fallback)
Timers acumuladossetInterval criado várias vezes sem guardar o idGuardar o id; clearInterval antes de criar outro

11. Armadilhas frequentes (e dicas para revisar código de IA)

  • Um só await: sem o segundo (await resposta.json()) você recebe uma Promise, não os dados.
  • Achar que 404 cai no catch: não cai; use response.ok.
  • Esquecer encodeURIComponent: "São Paulo" quebra a URL.
  • results[0] sem checar: cidade inexistente gera TypeError.
  • setInterval dentro de um clique: cada clique cria um timer novo; guarde o id e pare o anterior.
  • Tempos em segundos: setTimeout e setInterval usam milissegundos.
  • innerHTML com dado de fora: use textContent.
  • Mensagem de erro que some sozinha ou só muda de cor: falha de acessibilidade.
  • Código da IA: a IA entrega o "caminho feliz". Pergunte-se: e na 1ª visita? e sem rede? e com 404? e se negarem a permissão? e se eu clicar 5 vezes? E só use o que você consegue explicar.
